## 圈人能力：分群类型（后台配置）

后台「用户分群 / 新建」里 **分群类型**（必填）支持以下四种：

| 类型 | 说明 |
|------|------|
| **规则分群** | 按规则条件直接圈人 |
| **手动分群** | 人工指定人群 |
| **组合分群** | 在已有规则分群基础上，用交并集与多条件组组合出复杂人群（**策略设计常用，见下节**） |
| **实时分群** | 按实时更新策略圈人 |

---

## 组合分群（重点）

组合分群用于：**从已有规则分群里挑选多个「子人群」，再在右侧用逻辑运算拼成最终人群**。交、并、多组嵌套都可以实现，适合「既要 A 又要 B」「A 或 B」「多段漏斗」等复杂策略。

### 1. 基本配置

- **分群类型**：选择「组合分群」。
- **更新方式**：示例中可为「实时更新」——组合结果随底层规则分群数据变化而更新（具体以后台可选项为准）。

### 2. 左侧：规则库（选要参与组合的组）

- **作用**：展示已配置好的**规则分群**列表，从中勾选要参与组合的人群。
- **典型示例**（仅作能力说明，名称以实际后台为准）：
  - 账户内无券的用户  
  - 券到期 3 天内用户  
  - 【0-1】注册当天未下单  
  - 有 1.99 券的用户  
  - 首单后若干天未二单等行为标签  
- 在左侧**选中**的规则分群，会进入右侧组合区参与运算。

### 3. 右侧：组合逻辑与多条件组

- **作用**：在这里定义**怎么组合**左侧选中的规则分群。
- **组内逻辑**：同一组内多个规则之间，可用 **交集（∩）**、**并集（∪）** 等（界面以图标切换，如 A∩B、A∪B）。
  - 示例：`【0-1】注册当天未下单` **∩** `有 1.99 券的用户` → 表示「注册当天未下单且账户里已有 1.99 券」的人。
- **多条件组**：支持 **组 1、组 2 …**，组与组之间可再设交/并；可用 **「+ 新增条件组」** 增加多组，实现「(条件组 A) ∪ (条件组 B)」或更复杂结构。
- **策略含义**：  
  - 先在各规则分群里把「单条件人群」定义清楚；  
  - 在组合分群里用交并集和多组，表达「不冗余补券」「第 N 单阶段且当前券状态」等**复合条件**，无需所有逻辑都塞进一个规则分群。

### 4. 与字段清单的关系

- **规则分群**侧：依赖上文「可用字段」及后台配置规则。  
- **组合分群**侧：不新增字段，而是**对已有规则分群做集合运算**；因此策略设计时要同时想：**哪些用单条规则分群**、**哪些必须拆成多个规则分群再在组合里交并**。

## 业务约束（本场景）

- 先做塞券，不做触达
- 新人主链路希望承接前三单：1.99 → 2.99 → 5 折
- 不允许券冗余
- 若用户当前仍有有效 2.99，则不继续补 2.99

## 分析 / 输出要求

- 结论先行
- 明确「能做 / 不能做」
- 直接给后台圈人规则
- 说明哪些字段该用，哪些不建议作为主条件
