# 实验复盘模板库

## 目录用途

这里专门维护线上运营实验的复盘规则、提示词、样例和迭代记录。

适用范围：
- 触达实验
- 塞券策略
- 弹窗资源位
- 新客召回
- 滚动培养
- 任务活动
- 其他通过 AB、分群包、尾号分流等方式上线的运营动作

这套模板的目标不是“生成一段看起来像分析的文字”，而是稳定产出可决策的实验复盘结果。

当前主模板已经覆盖三类场景：
- 通用结果层实验
- 任务类活动
- 分享有礼活动

当前主模板的默认交付原则是：
- 线上跑数优先
- 出数优先于补链路
- 结果层优先于显著性、CAC、专项链路
- 本地文档只做口径校验和业务解释
- 缺口单独说明，不阻塞阶段性复盘

## 当前模板的核心原则

1. 先确认核心假设，再开始分析
2. 默认先线上跑数，再写复盘
3. 优先把结果层打出来，再补链路和附加分析
4. 缺口必须显式写出，不能静默跳过
5. 输出结构固定，但表格字段按已取到的数据裁剪
6. 统计不显著时，只能讲方向，不能折算收益
7. 结论要先说谁优谁弱、差多少、是否已判断显著性
8. 任务类活动优先出结果层，任务链路能补再补
9. 分享有礼优先出结果层，裂变链路能补再补
10. 所有结果表必须包含 `单杯实收`，且“人均”类指标默认以当期下单用户为分母（即只计算实际购买人），保持人均口径一致。

## 使用方式

默认把下面两类材料一起喂给 AI：

1. 实验背景材料
   - 实验名称
   - 实验编号 / 实验层
   - 上线时间
   - 实验组与对照组定义
   - 观察窗
   - 业务目标

2. 数据材料
   - 线上跑数得到的分组累计结果
   - 线上跑数得到的日度结果
   - 显著性检验或显著性检验原始输入（有则提供）
   - 任务 / 裂变 / 发券等补充链路指标（有则提供）
   - 缺失项说明、最大回刷日期、失败原因

然后使用：
- [主模板](./prompts-提示词/universal-experiment-review-prompt-通用实验复盘Prompt.md)

## 后续维护约定
