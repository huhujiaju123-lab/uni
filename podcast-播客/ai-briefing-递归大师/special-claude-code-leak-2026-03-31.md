## 内容结构

### 一、先定性：这不是“模型泄露”，而是“Agent 客户端结构曝光”

- Claude Code 不是模型本身
- 模型仍在 Anthropic 服务器
- 真正被看见的是本地 Agent harness（执行骨架）

### 二、再拆核心：为什么它的心脏不是 prompt，而是循环

- `query()` / `QueryEngine` 是对话生命周期管理器
- 本质是“观察 → 判断 → 调工具 → 读结果 → 再判断”的闭环
- 这比“一次性把问题扔给模型”高了一个系统层级

### 三、工具与权限：为什么强 Agent 一定要把危险动作包进制度里

- 工具不是随便调用，要有统一注册、校验、回传
- 权限不是 UI 按钮，而是策略层
- 这决定了 Agent 能不能真正进生产环境

### 四、多 Agent：为什么要 worktree 隔离

- 多个 worker 同时改代码，最大的风险不是“慢”，而是互相踩
- `git worktree` 隔离，本质上是给每个子 Agent 单独工位

### 五、上下文压缩与记忆：为什么 Agent 不是记得越多越强

- 上下文窗口有限
- 所以 Claude Code 把“压缩”做成系统能力，而不是临时补丁
- `Microcompact / Snip Compact / Auto Compact / Session Memory`
- 真正高级的地方是：把“忘什么、留什么”制度化

### 六、MCP 与 IDE Bridge：为什么它开始像操作系统

- MCP 让外部工具接入变成标准协议
- IDE Bridge 让终端、编辑器、权限弹窗、诊断信息打通
- 状态管理把 UI、模型、任务、工具、桥接统一收口
