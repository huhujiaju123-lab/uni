`未来工程师最重要的工作，不再是手写每一行代码，而是设计让 Agent 能持续产出好代码的环境。`

所以这期不适合塞进日更拼盘，适合单独做成一集特别版。

## 节目核心命题

这期节目只讲一个问题：

`Harness Engineering 到底是什么，为什么它不是 Prompt Engineering 的升级版，而是软件工程角色的一次换挡。`

听众要带走三层理解：

1. OpenAI 这个实验到底做了什么
2. Harness Engineering 和普通 AI 编程有什么本质差别
3. 普通 Builder 现在就能抄走哪些做法

## 核心信息提炼

### 一、先定性：它不是“AI 会写代码”，而是“人类改成掌舵”

- 五个月
- 零手写代码
- 一百万行级别产出
- 人类主要做拆任务、搭环境、定反馈回路

一句话总结：

`Humans steer. Agents execute.`

这句是整篇文章的总纲。

### 二、真正的变化不是模型更强，而是执行环境更完整

OpenAI 的关键不是“Codex 会写”，而是他们把以下东西做成了系统：

1. 工具
2. 测试
3. 评审循环
4. 可观测性
5. 仓库知识地图
6. 架构守卫
7. 漂移清理

所以 Harness Engineering 的白话定义可以这样讲：

`不是教模型说话，而是给 Agent 造工位、造规矩、造仪表盘、造护栏。`

### 三、最适合播客展开的 5 个点

#### 1. 从空仓库开始

- 连初始仓库都不是“有人类代码打样”
- 第一版 AGENTS.md 也是 Agent 写出来的
- 目的不是炫技，而是逼自己解决“没有人工兜底时，系统怎么还能走起来”

#### 2. 工程师角色重构

- 以前是执行者
- 现在更像产品化的舵手、环境设计师、质量控制者
- 从“自己写”转成“定义什么算写得好”

#### 3. 闭环测试与可观测性

- Agent 直接看 UI、日志、指标、trace
- “启动要小于 800ms”这种目标才变得真正可执行
- 没有证据回路，Agent 只是在猜；有了证据回路，Agent 才算在做工程

#### 4. AGENTS.md 不是百科全书，而是导航地图

- 大文档会把上下文打爆
- 真正有效的是“短入口 + 深知识库”
- 这是非常适合讲给《递归大师》听众的一条方法论，因为它和你现在做 AI 协作的习惯直接相关

#### 5. 架构围栏与垃圾回收

- Agent 会复制模式，好的坏的都复制
- 所以要有 linter、CI、结构测试、质量评分、后台修复任务
- 技术债不再只靠人类周末清理，而是要持续自动回收

## 节目角度

这期不讲成“OpenAI 好厉害”。

讲法要更像：

`为什么 Prompt Engineering 只是起点，到了 Agent 时代，真正拉开差距的是 Harness。`

可用的类比：

- Prompt Engineering = 教实习生一句一句怎么回答
- Harness Engineering = 给实习生安排工位、SOP、质检、日志系统、版本库和晋升制度

这个类比会让听众一下就听懂。
